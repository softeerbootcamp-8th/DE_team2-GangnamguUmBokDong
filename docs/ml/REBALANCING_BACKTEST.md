# 재배치 정책 소규모 백테스트

이 도구는 시간대별 실측 재고와 시민의 실제 대여·반납 기록을 같은 초기 상태에서
재생하여 재배치 정책의 품절 대여소-시간과 작업량을 비교한다. Airflow 운영 DAG가
아니며, 경로 알고리즘을 수정할 때 동일 조건으로 다시 실행하는 오프라인 평가 CLI다.

## 실행

`loader` 디렉터리에서 실행한다.

```bash
uv run --frozen python -m evaluation.rebalance_backtest \
  --date 2025-01-17 \
  --center hangnyeoul \
  --start-hour 6 \
  --duration-hours 6 \
  --max-stops 5 8 \
  --rental-csv "../data/issue163-full-year/bootstrap/서울특별시 공공자전거 대여이력 정보_2501.csv" \
  --stock-csv "../data/issue163-full-year/bootstrap/대여소별 공공자전거 대여가능 수량_2501.csv"
```

결과는 기본적으로 `data/backtest-results/`에 JSON과 Markdown으로 생성된다. 원천
CSV는 Git에 포함하지 않고 로컬 bootstrap 자산을 사용한다.

## 비교 의미

- `실제 기존 운영`: 시간대별 실측 재고에서 직접 계산한 품절 대여소-시간이다.
- `재배치 없음`: 시작 재고에 실제 시민 대여·반납만 재생한다.
- `현재 route-v2`: 운영 코드의 planner를 그대로 호출하며 트럭 용량과 작업 단위
  제한을 보존한다. `--max-stops`에 여러 값을 주면 운영 기본값을 바꾸지 않고 동일한
  수요·이동 대수 상한에서 작업당 대여소 수를 비교한다.
- 평가 구간의 모든 정시 재고와 좌표가 있는 대여소만 비교 집합에 포함한다. 목표일에
  이용이 없어 내부 ST ID를 관측하지 못한 대여소에는 경로 계산용 synthetic ID를
  부여하되, 거리·재고·수요에는 원천 실측값을 사용한다.
- 기존 운영 이동 예산은 `다음 실측 재고 - (현재 재고 - 대여 + 반납)`의 양·음
  잔차 중 작은 쪽으로 추정한다. 권역 외 이동과 정비·분실·데이터 오차는 별도
  불균형으로 보고한다.

현재 route-v2의 작업 필요량은 평가 구간의 미래 실제 수요로 만든다. 따라서 결과의
근거 등급은 `exploratory_oracle`이다. 이는 경로 구성의 잠재 효과와 제약을 비교하는
상한 실험이며, 역사 시점에 생성한 모델 예측을 입력하기 전에는 시스템의 실제 개선율로
발표하면 안 된다.

## 최초 좁은 실험

2025년 모델의 미학습일인 2025-01-17, 학여울 권역 06:00~12:00을 실행했다.

| 항목 | 결과 |
|---|---:|
| 비교 대여소 | 295곳 |
| 관측 대여 | 1,783건 |
| 기존 운영 추정 이동 예산 | 112대 |
| 기존 운영 품절 대여소-시간 | 230 |
| 재배치 없음 품절 대여소-시간 | 244 |
| 최대 5곳 품절 대여소-시간 | 226 |
| 최대 5곳 작업 | 2경로·10정차·24대·144.5분 |
| 최대 8곳 품절 대여소-시간 | 225 |
| 최대 8곳 작업 | 2경로·11정차·24대·142.4분 |

두 설정 모두 재배치 없음에서 발생한 관측 대여 미충족 25건을 이 탐색 시뮬레이션에서
모두 해소했다. 최대 8곳은 최대 5곳보다 품절 대여소-시간이 1 낮고 추정 차량시간도
2.1분 짧았으며, 실제 기존 운영보다 품절 대여소-시간이 2.17% 낮았다. 이 한 구간에서는
8곳이 근소하게 우세하지만 일반적인 최적값이라고 결론낼 수 없다. 또한 미래의 실제
수요로 작업 필요량을 계산했으므로 이는 **경로 제약 아래의 잠재 상한**이며 모델을
포함한 전체 시스템의 개선율로 인용할 수 없다.

## 발표 근거로 승격하기 위한 조건

1. 평가 시점 이후 정보를 쓰지 않은 역사 시점 모델 예측을 저장하고 입력한다.
2. 운영자 작업 로그로 잔차 기반 이동량 추정의 정확도를 검증한다.
3. 트럭 수·차량 작업시간·이동 대수를 기존 운영과 동일하게 제한한다.
4. 모델 학습일을 제외한 여러 날짜에서 평균과 날짜별 분포를 함께 보고한다.
5. 가능하면 실제 대여 실패 로그 또는 현장 A/B 실험으로 잠재 수요를 평가한다.
