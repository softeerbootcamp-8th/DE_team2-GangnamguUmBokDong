## 2. 공용 매핑 모듈

공용 매핑 모듈을 만들어서 실버 데이터에서 추론기, 서빙기가 데이터를 가져올때

이 모듈을 거쳐서 라이브러리처럼 데이터를 가져오게 설계

- 저장 모듈 : 브론즈 저장, 1차 정제 저장, normalizer 저장, 추론후 결과 저장

- 읽기 모듈 : normalizer 입력 읽기, 추론용 데이터 읽기, 골드데이터 서빙용 읽기

### 대상
서울시 시설관리공단 교통사업본부 공공자전거운영처 공공자전거관리소 분배업무 운영·관리 담당자

### 문제
서울시 전역의 대여소를 대상으로 품절 및 과잉 주차 문제를 선제적으로 해결하기 위해, 어느 대여소 간에 몇 대의 자전거를 이동시켜야 하는지 실시간으로 판단하기 어렵다.

(실시간으로 어떤 대여소가 잠재적인 품절/과잉주차 위험이 더 높은지 판단하기 어렵기 때문)


### 해결방법
실시간으로 관제센터에서 기사들에게 어떤 작업들을 지시할지 정해주는 시스템을 만든다

- 대여소 별 근처 날씨, 인구, 대여이력 등의 데이터를 이용해 향후 12시간동안의 대여/반납 수요를 예측하고, 이를 기반으로 대여소별 품절/과잉주차 위험도를 산정해 어느 대여소 간에 몇 대의 자전거를 옮겨야 할지, 필요 재배치 작업 목록을 보여준다.


| INPUT | PROCESSING | OUTPUT |
|---|---|---|
| 따릉이 대여 이력 | 향후 12시간 대여 수요 예측 | 필요 재배치 작업 목록<br>(어디에서 어디로 몇 대를 옮길지 제시) |
| 따릉이 대여소 현황 | 향후 12시간 반납 수요 예측 | 대여소별 품절 위험도 |
| 날씨 데이터 (실시간·일기예보) | 서울시 POI 부근 인구 보정 데이터 | 대여소별 과잉 주차 위험도 |
| 서울시 인구 데이터 (생활인구·POI 인구) | - | - |
| 서울시 문화행사 데이터 | - | - |

### 상세

데이터 수집 후 적재

대여소 별 미래 대여/반납 수요 예측

대여소 별 품절/과잉 취약 정도를 판단하여 작업 우선순위 산출

한달마다 모델 정확도 테스트 후 일정 기준 미달시 그동안 새로 적재된 데이터를 추가하여 재학습

### 필요 자원

EC2 4대 (에어플로우, 데이터 수집/정제, 추론, 백엔드 API)

EMR serverless (피처 데이터 제작/학습용 스파크 작업)

RDS (실시간 서비스용 골드 데이터 적재)

S3 (브론즈/실버 데이터 적재)
