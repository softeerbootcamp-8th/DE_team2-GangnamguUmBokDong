## 2. W6M1

서울 따릉이 대여 데이터 수집 파이프라인 요구사항

### (1) 프로젝트 개요

Airflow DAG 기반으로 서울시 공공 API(tbCycleRentUseDayInfo)에서 따릉이 대여 데이터를 수집 → 정제 → 품질 검사 → DB 적재하는 파이프라인.

- 수집 대상 일자: 2026-06-27, 2026-06-28

- 일별 예상 규모: 약 10만 건 (1000건씩 100회 호출)

### (2) API 명세 (tbCycleRentUseDayInfo)

요청 인자

변수명|타입|필수|설명
|--|--|--|--|
KEY|String|✅|OpenAPI 인증키
TYPE|String|✅|응답 형식 (xml / json)
SERVICE|String|✅|tbCycleRentUseDayInfo
START_INDEX|Integer|✅|요청 시작 행 번호
END_INDEX|Integer|✅|요청 종료 행 번호
RENT_DT|String|✅|대여일자 (YYYYMMDD)

출력값

| No | 출력명 | 설명 |
|---:|---|---|
| 공통 | `list_total_count` | 총 데이터 건수 |
| 공통 | `RESULT.CODE / MESSAGE` | 요청 결과 코드·메시지 |
| 1 | `RENT_DT` | 대여일자 (YYYYMMDD) |
| 2 | `RENT_ID` | 대여소번호 |
| 3 | `RENT_NM` | 대여소명 |
| 4 | `RENT_TYPE` | 대여구분코드 |
| 5 | `GENDER_CD` | 성별 |
| 6 | `AGE_TYPE` | 연령 |
| 7 | `USE_CNT` | 대여건수 |
| 8 | `EXER_AMT` | 운동량 |
| 9 | `CARBON_AMT` | 탄소절감량 |
| 10 | `MOVE_METER` | 이동거리(M) |
| 11 | `MOVE_TIME` | 이용시간(분) |

### (3) 페이지네이션

Offset(시작·끝 인덱스) 방식으로 수집한다.

- 1회 호출당 최대 1000건 (API 자체 제한)

- START_INDEX를 1001씩 증가시키며 list_total_count에 도달할 때까지 반복

- 두 날짜(06-27, 06-28)의 모든 페이지를 빠짐없이 수집

- 호출마다 로그 기록: 요청 일시 / 대여 일자 / 시작 인덱스 / 끝 인덱스 / 성공 여부 / (성공) 데이터 개수 / (실패) 에러 메시지

### (4) DAG 처리 흐름

    ① 데이터 수집 (API 호출)
    ② 데이터 건수 체크
    ③ 데이터 정제 (결측치 제거 등)
    ④ 정제 테스트 → 오류 시 로그 & 알림
    ⑤ 데이터 DB 저장
    ⑥ 집계 데이터 DB 저장 (통계 계산)
    ⑦ 데이터 품질 검사 (스키마 비교)

재시도 정책

| 단위 | 정책 |
|---|---|
| API 요청 | 실패 시 2회 재시도 (간격 5초) |
| Task | 2회 재시도 후에도 계속 실패하면 DAG 종료 |
| DAG 종료 이후 | 10분 후 해당 일자 데이터를 처음부터 다시 호출하고 알림 송출 |
| 재시도 시 | 해당 요청 건을 삭제한 후 수집 단계로 복귀 |

Task 정의 기준: 알림을 받고 싶은 작업 단위 / 작동 시간을 측정하고 싶은 작업 단위

### (5) 스케줄링 & 설정

### (7) 데이터 정제 규칙

삭제 (결측치 처리)

- 데이터 타입 위배, 빈 데이터, PK Null → 삭제

    - PK: RENT_DT, RENT_ID

Null로 변환 후 저장 (로그 기록)

- 음수 값, 숫자 변환 실패 값 → Null 처리 + 로그 기록

- PK가 아닌 결측치 → Null로 저장

값 판정 기준

값|정상 컬럼|비정상 컬럼
|--|--|--|
0 값|이동거리, 대여건수, 이용시간, 탄소절감량|대여일자, 대여소번호, 대여소ID, 나이

유의 케이스

값은 비정상이나 대여건수는 정상인 경우 → 별도 처리 필요

- 예: GPS 장치만 고장난 자전거의 대여 기록을 전부 결측치로 삭제할지 판단 필요

특정 날짜 데이터가 전혀 없음

필수 컬럼 누락

동일 기간·대여소 중복 존재

정제 전후 합계 검증 불일치

모든 결측치 발생 시 Airflow log 기록 → 제외 기준이 잘 작동했는지 분석 가능

### (8) 데이터 품질 검사

정제된 데이터에 대해 수행
