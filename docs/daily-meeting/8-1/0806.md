## 2. RDB vs S3

우리 시스템은 api로 데이터를 수집해서 바로 정제한 후 RDB에 저장한다. 

- 즉 브론즈 데이터는 저장하지 않고 실버 데이터를 RDB에 저장한다.

- 그 후 RDB에서 모델로 추론을 해서 골드 데이터를 만들고 서빙한다.

정석은 api로 데이터를 수집해서 일단 브론즈 데이터를 S3에 저장한다.

- 그 후 S3에서 브론즈를 꺼내서 정제를 해서 실버로 만들고 다시 S3에 저장한다.

- 그 후 RDS의 실버를 추론해서 골드 데이터로 만들고 서빙한다.



우리 시스템

- 장점 : S3에 저장하지 않고 RDB에서 바로 실시간 조회를 할 수 있다.

- 단점 : 특정 시점의 api 호출 데이터가 정제 전에 어땠는지 이후에 알 수 없다.



정석

- 장점 : 이후에 감사, 복구, 추적이 가능하다.

    - 양이 많은 데이터의 경우 S3에서 추론 머신에 넣을 때 spark를 쓸 수 있다.

- 단점 : S3에서 데이터를 꺼내오는 작업이 추가된다.



일단 브론즈 데이터를 S3에 저장한다.

동시에 같은 데이터를 실버로 정제해서 RDS에 저장한다.

- 현직자 분들에게 피드백 받기 전까지 확정
