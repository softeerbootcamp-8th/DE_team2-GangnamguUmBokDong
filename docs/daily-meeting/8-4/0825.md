## 3. 찾은 수정점

compaction

- 현재는 daily_compaction을 통해서 6일전을 기준 날짜로 다시 api 호출해서 그동안 새로 쌓인 데이터를 가져와서 저장한다.

- 이때 원래 1시간 단위로 5분마다 저장하던 것을 1시간 단위로 compaction해서 저장한다.

hot bronze, cold bronze

- 지금 30일이 지난 hot bronze 데이터는 삭제된다.

| 단계 | 현재 `develop`의 실제 동작 |
|---|---|
| 수집 | Airflow → Collector CLI |
| API 호출 | Source별 Adapter, Pagination / Concurrency / Retry |
| Bronze | Raw Response를 즉시 `JSON.gz`로 저장 |
| Normalize | Adapter별 Raw JSON → Row 변환 |
| Validation | Type / Range / Required / Policy 검증 |
| Quarantine | 폐기된 Row를 JSONL로 저장 |
| Silver | Content-addressed Immutable Parquet |
| Source Authority | Revision 기반 Source Snapshot Manifest |
| Backfill | 실패한 Bronze Part만 재수집 |
| Rental Replay | 늦게 반납된 이력 때문에 `--force`로 재수집 |
| Compaction | 일별 Silver → Archive Parquet |
| 생활인구 | Daily Nowcast + Realtime POI Normalization |
| Serving Plan | Source / Model / Station의 정확한 Snapshot Pinning |
| Inference | 전체 Station × 12 Horizon |
| Inference Input | Lag, Population, Weather, Stockout, Profile Fallback |
| Inference Output | Immutable 7-column Parquet + Manifest |
| Gold Finalize | Station / Stock / Demand / Weather의 원자적 Publication |
| Urgency | Current + History + Forecast로 Station Priority 계산 |
| Route | 정확한 Current Urgency를 기준으로 차량 작업 경로 생성 |
| Serving | RDS Gold → FastAPI → Dashboard |
| 장애 대응 | 새로운 Publish 실패 시 기존 Successful Gold 유지 |
| Dashboard HA | Last-known-good Urgency 허용 |
| 실제 배차 | Stale 데이터는 새로운 Route 생성에 사용하지 않음 |
